# Execution Platform Runbook

## Overview

Pi-PM executes approved recommendations through the unified execution API. Paper mode is the default; live Zerodha Kite execution requires explicit safety gates.

## Workflow

1. **Recommendation** — generated by the recommendation engine (unchanged).
2. **Human approval** — `POST /api/v1/recommendations/{result_id}/approve` with `decision=APPROVED`.
3. **Execution request** — `POST /api/v1/execution/orders` (OWNER/ADMIN only).
4. **Lifecycle** — `EXECUTION_PENDING → SUBMITTED → ACCEPTED → FILLED`.
5. **Portfolio update** — occurs only on `FILLED`.

Legacy portfolio endpoints (`POST /api/v1/portfolio/trades/entry|exit`) route through the same execution service.

## Paper Execution (Default)

```bash
# 1. Approve recommendation
curl -X POST /api/v1/recommendations/{id}/approve \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"approval_type":"ENTRY","decision":"APPROVED"}'

# 2. Submit execution
curl -X POST /api/v1/execution/orders \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Portfolio-Id: $PORTFOLIO_ID" \
  -d '{"recommendation_id":"...","approval_id":"..."}'
```

## Monitoring

| Endpoint | Purpose |
|----------|---------|
| `GET /api/v1/execution/orders` | List orders |
| `GET /api/v1/execution/orders/{id}` | Order detail |
| `GET /api/v1/execution/events` | State transition audit |
| `GET /api/v1/execution/health` | Adapter health |

## Configuration

```bash
GET  /api/v1/execution/config
POST /api/v1/execution/config  # OWNER/ADMIN
```

`portfolio_configs.execution_mode` defaults to `PAPER`.

## Cancel

```bash
POST /api/v1/execution/orders/{id}/cancel
```

Only non-terminal orders can be cancelled.

## Troubleshooting

| Symptom | Check |
|---------|-------|
| 422 on submit | Recommendation not `APPROVED`, or missing approval record |
| 403 on LIVE | `ENABLE_LIVE_TRADING` not set |
| No portfolio change | Order status not `FILLED` — check `/execution/events` |
